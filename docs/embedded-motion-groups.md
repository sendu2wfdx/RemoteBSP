# STM32 跨板运动组参与者

STM32 公共 Remote Core 在启用 `CONFIG_REMOTEBSP_MOTION` 时编译运动组参与者，
处理 `MotionGroupPrepare`、`MotionGroupCommit` 和 `MotionGroupAbort`。关闭运动模块时，
参与者源码不参与构建，`rbsp_core_t` 也不包含其状态。

## 事务行为

- `PREPARE` 校验协议身份、启动代次、节点开始时刻、序列、资源 ID、步频和队列
  约束，并确认请求会话持有段内全部 STEPGEN 轴的有效独占租约；它只保存一个
  冻结段和资源位图，不修改运动队列，也不产生 STEP。
- `COMMIT` 必须由相同会话携带完整相同的冻结身份。只有这一步才把冻结段提交给
  `rbsp_motion_queue_t`，提交前还会再次核对全部冻结租约。重复 `PREPARE` 和
  `COMMIT` 不会重复入队。
- 不同身份、不同内容或不同会话的请求会被拒绝。预备或已武装期间，普通
  `MotionEnqueue` 返回资源忙，避免插入段破坏冻结结果。
- 组段自然完成后会保留 `group_id + plan_generation` 完成水位：普通入队恢复，
  但同组旧代次不能因请求缓存淘汰而复活；更高代次可以继续。
- `ABORT` 在已武装时调用现有运动队列安全停机。普通 `MotionAbort` 也会先使预备
  事务失效并锁存 `Aborted` 故障。首次调度或 compare 安排失败时，刚提交的段会
  立即清空并进入安全输出状态。

## STEPGEN 租约生命周期

公共 Remote Core 为每个编译期 STEPGEN 轴保留一个静态租约槽，不使用动态内存，
只支持 `Exclusive` 模式。`ResourceContract` 将轴声明为可写、独占写、支持租约且
操作前必须持有租约；租期范围与 Mock 一致，为 100 至 60000 毫秒。

- `ResourceAcquire` 返回非零 `lease_id`；同一请求的重传由 Remote Core 请求缓存
  幂等应答，不会重复分配。已有租约时，其他请求或会话得到 `ResourceBusy`。
- `ResourceRenew` 和 `ResourceRelease` 必须同时匹配资源、会话与令牌。状态查询会
  报告占用会话、租期和剩余时间，但不回传能力令牌。
- 普通 `MotionEnqueue` 与运动组 `PREPARE` 都要求请求会话持有段内每个轴的有效
  独占租约；同一运动队列有未完成段时不能混入另一会话的段。
- 租约释放或到期会使涉及该轴的预备事务失效；若段已武装或正在运行，会清空运动
  队列、锁存 `Aborted` 并经现有运动服务立即将 STEP/EN 落入安全状态。即使租约在
  `PREPARE` 后失效，`COMMIT` 的二次校验也不会允许段入队。
- 传输层确认会话断开时可调用 `rbsp_core_release_session()`：它释放该会话的全部
  STEPGEN 租约、使预备/已武装事务失效、停机，并删除该会话的请求去重缓存，避免
  旧的 Acquire 成功响应在会话结束后复活。
- `rbsp_core_poll()` 和每次请求处理都会检查到期。实际停机延迟受主循环最坏轮询
  延迟约束；当前不是独立硬件租约看门狗，这一延迟仍需在实体板压力测试中量化。

节点重新执行 `rbsp_core_init()` 后，租约、会话所有权、运动队列与请求缓存均从空
状态开始。CAN 链路本身无法凭静默可靠判断会话已经消失，因此正常断链应由上层
显式触发 `rbsp_core_release_session()`，租期到期是最终兜底。

## 启动代次和当前硬件边界

`rbsp_hal_t::motion_boot_epoch` 必须返回本次 MCU 启动唯一的非零 64 位代次；返回
零或不配置表示板卡没有可靠启动代次。此时普通单板运动仍可用，但 `TimeSync` 和
运动组命令返回 `UnsupportedCapability`，不能进入跨板同步。

不能用 UUID、从零启动的定时器、未初始化 RAM 或启动时序抖动伪造启动代次。
当前 F072、F103、G431 板级代码尚未提供经过掉电与快速复位验证的可靠来源，因此
实体固件默认保持上述安全降级。后续需要选定耐久的持久化启动计数器或可靠硬件
随机源，并在板卡上验证唯一性后才能开放跨板同步。

STEPGEN 租约的协议和纯软件安全闭环已与 Mock 对齐，但当前三块实体板仍没有可靠
`motion_boot_epoch`，所以它们只能使用租约保护的普通单板运动；跨板运动组入口仍
保持关闭。硬件定时精度、主循环最坏延迟、复位瞬间 EN/STEP 电气状态和持久启动
代次都必须在统一板卡环境中验证。
