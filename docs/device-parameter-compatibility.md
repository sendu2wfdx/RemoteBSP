# 设备参数兼容性

设备参数持久区与资源映射独立。当前持久格式版本为 `v1`，schema 版本也为 `v1`；
两者版本号含义不同，不能互相代替。本文约定只涉及 MCU 无关的双页存储软件行为，
不构成实体 Flash 掉电、升级保留或跨板验证结论。

## 兼容矩阵

| 输入 | 启动结果 | 后续提交 | 说明 |
|---|---|---|---|
| 无有效页 | 空存储，generation 为 0 | 首次提交写 generation 1 | 不自动写默认值 |
| 较旧 schema 生成的完整 v1 页 | 接受 | 迁移到新页 | 允许缺少当前新增字段 |
| 当前已知、长度合法的短可变字段 | 接受 | 按原值迁移 | 例如 1 字节设备名称 |
| 当前已知、短于最小长度的字段 | 整页拒绝 | 不提交 | 防止按错误布局解释 |
| v1 中当前未知的记录 | 接受为 opaque | 记录头、保留位、值和对齐填充逐字节迁移 | 本版本不解释其值 |
| 声明记录数之后仍有记录/尾部 | 整页拒绝 | 不提交 | 不允许无法证明可保留的字节 |
| 未来持久格式版本 | 整页拒绝 | 不提交 | 失败关闭，等待理解该格式的新固件 |
| CRC、commit marker、长度或重复 ID 损坏 | 整页拒绝 | 选择另一完整页 | 两页都无效则为空存储 |
| 两个有效页代次跨 `UINT32_MAX -> 0` | 选择 0 | 下一次为 1 | 使用有符号差的 32 位串行数比较 |

未知记录只有在 v1 记录头、长度边界、唯一 ID、整页 CRC 和提交标记都有效时才被接受。
更新任一已知参数时，存储层会把未知记录复制到新镜像；若容量不足则整次写入失败，不能
通过丢弃未知记录腾出空间。

## 默认值与读取来源

`rbsp_device_param_store_resolve()` 将读取来源明确分为：

- `PERSISTED`：Flash 中存在该记录；
- `DEFAULTED`：记录缺失，且当前 schema 允许空值作为默认值；当前包括制造批次、制造日期
  和设备名称；
- `ABSENT`：记录缺失且没有安全默认值，例如序列号、UUID、硬件版本和 ADC 校准。

默认值只属于读取视图，不会写入 Flash、增加记录数或推进 generation。未知 ID 不属于当前
schema，`resolve` 返回失败；如需维护 opaque 记录，存储内部仍会负责无损迁移。

## 黄金样例

`device_parameter_store_tests` 直接构造固定的小端 v1 页，而不是调用生产写入路径生成测试
输入，覆盖旧 schema 缺项、短长度、未知记录、未来版本、默认值来源、CRC 回退和代次回绕。
这能同时锁定读取器与写入器的兼容契约，避免两者以相同错误互相验证。
