# 设备参数本地审计

RemoteBSP Studio 的设备参数写入和恢复只能由显式 CLI 命令发起。两条命令都要求
同时指定 `--audit-dir` 和 `--audit-key-file`；审计意图成功持久化以前，不会调用
toolbusd，也不会修改设备。

审计密钥文件必须是普通文件，内容为至少 32 字节的密钥，或 64 位十六进制表示。
密钥不会写入记录；记录只保存密钥摘要的前 16 位作为 `key_id`。审计目录必须为空，
或包含正确的 RemoteBSP 目录标记。单目录最多保存 4096 次操作，每份记录最大
32 KiB；达到边界时拒绝新的参数写入，避免出现“已修改但没有意图记录”。

每次操作使用一个独立 JSON 文件。第一阶段原子写入 `intent`，设备操作结束后再原子
替换为包含 `intent` 和 `terminal` 的完整记录。进程在操作期间异常退出时，单独存在的
`intent` 表示终态未知，不能当成成功。终态分为：

- `success`：操作返回了新快照；
- `failure`：未确认任何参数写入；
- `partial_failure`：错误明确报告已有若干项完成，必须重新读取代数后人工处置。

事件使用 HMAC-SHA-256 串联，启动审计存储时会检查已有记录。字段、顺序、密钥标识或
事件内容被修改后，校验会失败。记录包含节点 ID、UUID、预期及最终代数、参数 ID、
字节数和值的 SHA-256，不包含参数原文或 Base64。当前操作者来源明确记作
`local_cli`、`authenticated: false`；这表示边界只能证明本机 CLI 发起，尚不能证明具体
人员身份。时间来自未证明可信的主机系统时钟，仅供排序。

示例：

```text
studio_cli.py device-parameter-write ... \
  --audit-dir ./parameter-audit \
  --audit-key-file ./parameter-audit.key
```

审计密钥应由操作系统权限保护并另行备份。删除或丢失密钥后，历史记录不能再验证；
本地 HMAC 也不等同于外部时间戳或不可删除的远端日志。
