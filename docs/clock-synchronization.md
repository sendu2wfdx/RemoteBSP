# 主机时钟同步模型

## 范围

本模块是跨板运动同步的主机侧前置算法，只负责把主机单调纳秒时间映射到单个 MCU
的自由运行计数器，并把模型纳入节点在线、分配和启动代次生命周期。当前已定义并验证
纯软件 `TimeSync v1` 请求/响应闭环，并已接入 `toolbusd` 的有界周期采样；它不修改
MCU 时钟、不下发运动，也不接触实体板。

实现位于：

- `toolbusd/include/remotebsp/toolbusd/clock_model.hpp`
- `toolbusd/src/clock_model.cpp`
- `toolbusd/include/remotebsp/toolbusd/node_registry.hpp`
- `toolbusd/src/node_registry.cpp`
- `protocol/include/remotebsp/protocol/time_sync.hpp`
- `mock_mcu/include/remotebsp/mock_mcu/time_sync_bsp.hpp`
- `toolbusd/include/remotebsp/toolbusd/clock_sync_manager.hpp`
- `tests/clock_model_tests.cpp`
- `tests/node_clock_registry_tests.cpp`
- `tests/time_sync_protocol_tests.cpp`
- `tests/time_sync_e2e_tests.cpp`
- `tests/clock_sync_scheduler_tests.cpp`

它输出可审计的比例、偏移参考点、RTT、漂移、误差上界和同步状态，并由节点注册表
提供安全换算门。当前结果只供未来 PREPARE/READY/COMMIT 准入使用，不会下发运动。

## 节点生命周期与启动代次

`NodeRegistry` 只为“在线、已确认分配”的节点注册时钟模型。模型身份由
`node_id + boot_epoch` 共同确定：

- `boot_epoch == 0` 视为未知代次，拒绝注册；
- 同一组合重复注册是幂等操作，不会丢掉已收集样本；
- 同一 `node_id` 出现新的 `boot_epoch` 时，先构造并校验新模型，再原子替换旧代次；
- 样本、估计和换算都必须携带完全一致的 `boot_epoch`，旧代次不能访问新模型；
- 重新分配节点 ID、撤销分配确认、心跳宣告不同 ID、节点离线或显式重置时，立即删除
  对应模型；恢复在线后必须重新注册并重新积累样本；
- 默认最多保存 128 个当前模型，构造注册表时可设置更小的固定上限。达到上限后拒绝
  新节点模型，不驱逐仍在线节点，也不复用其他节点的状态。

发现和心跳协议不携带 `boot_epoch`，注册表不会从固件版本、计数器回绕或主机重连中
猜测代次。`TimeSync v1` 响应每次都返回 MCU 本次启动不变、重启后变化的非零
`boot_epoch`。真实固件以后必须从可靠启动身份源生成它；当前 Mock 支持测试显式指定，
默认实例则在每次构造时生成新的非零值。

`host_to_node_time()` 是唯一面向后续调度准入的安全换算接口。它依次检查节点存在、
在线且已分配、启动代次一致、目标不早于主机当前时刻、模型在目标时刻仍为 `SYNCED`，
以及误差上界不超过调用方门限。特别地，状态和误差在目标执行时刻计算，而不是只看
调用时刻，因此较远的未来目标会把继续老化纳入门限。任一检查失败都只返回原因，不
返回可误用的节点 tick。

## TimeSync v1 线协议与采样边界

系统命令 `TimeSync (0x0020)` 使用普通请求 ID、会话 ID、对象 ID 和既有请求去重机制。
请求载荷固定为 4 字节：

| 偏移 | 长度 | 字段 |
|---:|---:|---|
| 0 | 1 | 载荷版本，当前必须为 1 |
| 1 | 1 | flags，v1 必须为 0 |
| 2 | 2 | 保留，必须为 0 |

成功响应的通用状态字节之后是固定 36 字节同步载荷：版本、计数器位宽、flags、
`boot_epoch`、标称 tick 频率、节点接收 tick、节点发送 tick。所有多字节整数使用小端。
编解码拒绝错误长度、未知版本/标志、零 epoch、零频率、2～64 位范围外的位宽、超出
声明位宽的 tick，以及不可能或达到半回绕周期的节点处理时间。

主机时间不放进线协议，而在链路边界本地锁存：

1. `ClockSyncManager::poll_schedule()` 为在线且已确认分配的节点向 `RequestManager`
   注册请求；
2. `toolbusd` 在首帧实际交给 `LinkTransport::send()` 之前调用 `mark_sent()`；重试
   不会覆盖首发时间；
3. `toolbusd` 在完整响应重组完成后、协议解码和互斥锁等待之前锁存接收时间，并传给
   `accept_response()`；
4. 管理器匹配会话/请求/对象 ID，解析响应，按返回配置注册启动代次，再把四时间戳交给
   `NodeRegistry::add_clock_sample()`。

如果没有记录实际发送边界、响应来自错误节点路由、请求已取消、远端报错或载荷无效，
该交换不会生成样本。同一 `boot_epoch` 如果突然报告不同的 tick 频率或位宽，也会拒绝
而不会改写已有模型。`toolbusd` 在节点离线、已知节点从临时路由重新发现，以及请求
最终超时时，同时取消对应的待处理同步请求；恢复在线或重新确认分配后，从新请求重新
积累样本。

周期调度默认每个节点 500 ms 采样一次，最多跟踪 128 个节点、最多保留 128 个同步
请求，并且每次事件循环最多新派发 4 个请求。同一节点不会存在两个并发同步请求，节点
数量或请求数量达到上限时不会无界扩容。TimeSync 使用 System 流量类别和正常带宽准入；
包括重试在内都不会借用 Safety 的保证发送权限。准入失败时取消本次请求，等下一个周期
再尝试。

Mock 的 tick 来源被隔离在 `TimeSyncBsp`，Remote Core 只负责协议校验和字段映射，不
自行读取主机时钟。`MockTimeSyncBsp` 由显式启动原点、频率、位宽、初始 tick 和固定
响应处理 tick 决定输出；给定相同配置和输入时间必然得到相同结果，可确定性复现短计数器
回绕和节点重启。

## 四时间戳样本

一次同步交换产生：

| 字段 | 时钟域 | 含义 |
|---|---|---|
| `host_send_ns` | 主机 | 同步请求发出时刻 |
| `node_receive_tick` | MCU | MCU 尽早锁存的接收计数器值 |
| `node_send_tick` | MCU | MCU 发响应前锁存的发送计数器值 |
| `host_receive_ns` | 主机 | 主机收到响应时刻 |

主机时间必须来自同一个单调时钟。MCU 两个时间戳必须来自同一个连续自由运行计数器，
不能一个取系统毫秒、另一个取运动定时器。

每个样本计算：

```text
host_midpoint = host_send + (host_receive - host_send) / 2
node_midpoint = node_receive + (node_send - node_receive) / 2
host_rtt = host_receive - host_send
network_rtt ≈ host_rtt - node_turnaround / nominal_tick_rate
nominal_offset = node_midpoint - nominal_scale * host_midpoint
```

减去 MCU 处理时间后，`network_rtt / 2` 是链路方向不对称未知时的基本误差包络。
算法不会把偏移估计本身包装成比该物理边界更精确的结论。

## 输入约束与回绕

`node_counter_bits` 可配置为 2 至 64 位：

- 64 位输入视为已经扩展的单调计数，倒退直接拒绝；
- 较短计数器按模数展开为逻辑 64 位值；
- 相邻接收样本以及单次 MCU 处理时间必须小于半个计数器周期；
- 等于或超过半周期的跳变无法区分“向前跨越很久”和“时间倒退”，按
  `CounterAmbiguous` 拒绝；
- 原始值超出声明位宽按 `CounterOutOfRange` 拒绝；
- 逻辑 64 位展开即将溢出时拒绝，不静默回绕。

因此同步轮询周期必须明显小于半回绕周期。例如 1 MHz 的 32 位计数器约 71.6 分钟
回绕一次，实际同步间隔应远小于约 35.8 分钟的歧义边界。

主机样本中点和接收时间也必须严格前进。被拒绝的样本不更新计数器展开参考、滑动
窗口或模型。

## 低 RTT 选择与稳健拟合

模型维护固定容量滑动窗口，重建过程为：

1. 按估计 `network_rtt` 从小到大排序，RTT 相同时优先保留较新样本；
2. 只保留配置数量的低 RTT 样本，降低排队和调度暂停造成的偏移误差；
3. 按主机时间排序，并检查样本数和时间跨度；
4. 计算所有样本对的斜率，使用 Theil–Sen 中位斜率估计频率比例；
5. 选择中间主机时刻为参考点，以中位参考值估计偏移；
6. 用残差、半 RTT 和一个 MCU tick 的量化误差形成基础误差上界；
7. 用成对斜率离散度的稳健中位数估计漂移不确定度，并设置配置下限。

模型形式为：

```text
node_tick = reference_node_tick
          + scale_ticks_per_ns * (host_ns - reference_host_ns)
```

使用参考点表达而非巨大绝对截距，可以减少长时间运行后的浮点消减误差。STEP ISR
不会运行拟合；未来只在主机上拟合，并在运动段提交前把全局段边界换算为节点 tick。

`maximum_rate_deviation_ppm` 是板卡晶振与配置一致性的硬边界。拟合结果越界时模型
保持无效，不能用一个数学上可拟合但物理上不可信的频率启动运动。

## 状态与误差老化

状态只有三种：

| 状态 | 条件 | 运动准入 |
|---|---|---|
| `UNSYNCED` | 样本不足、跨度不足、拟合无效、查询时间倒退或模型过期 | 禁止跨板提交 |
| `SYNCED` | 模型有效、样本新鲜且当前误差上界不超过阈值 | 可以进入 READY 检查 |
| `DEGRADED` | 模型仍可解释，但样本变旧或误差上界越界 | 禁止新提交，已有事务按安全策略处理 |

误差随最后样本年龄增长：

```text
current_error_bound = base_error_bound
                      + sample_age * drift_uncertainty_ppm / 1_000_000
```

老化起点取实际入选拟合的最新样本；未入选的高 RTT 样本不能刷新模型。超过
`synchronized_max_age_ns` 先降级；超过 `model_expiry_ns` 变为未同步。即使数值
映射仍可计算，调用方也必须先检查同一时刻的 `estimate()`，不得使用过期模型执行
跨板运动。

建议运行时使用两个阈值：

- READY 阈值应严于运动组承诺，给提交确认和继续老化留余量；
- 运行停止阈值可稍宽，但一旦越界只能在共同安全边界停止或立即进入组安全状态，
  不能在运行中突跳已提交段的本地 tick。

## 确定性与限制

- 相同配置和相同样本顺序得到相同的选择、拟合和状态结果；
- 所有顺序检查、回绕展开和年龄计算使用整数；拟合使用 `long double`，测试使用物理
  误差容限而不是依赖特定位级浮点结果；
- 低 RTT 选择能抵抗高延迟/排队离群点，Theil–Sen 能抵抗少量时间戳残差离群点；
- 持续的单向链路不对称无法仅凭四时间戳完全识别，只能进入误差上界；
- 当前模型每个实例只对应一个节点和一个 `boot_epoch`。节点重启必须丢弃旧实例，
  不能把新计数器接到旧展开状态；
- 当前未估计温度模型，也不使用 CAN 硬件时间戳。未来增加更高质量时间戳时不能改变
  已有字段含义，应通过能力和样本质量标记演进。

## 已覆盖的软件测试

- `+80 ppm` 与 `-120 ppm` 的频率和双向时间映射；
- 固定上下行延迟不对称，并验证真实偏移误差落在误差上界内；
- 高 RTT 且强不对称的离群点，验证低 RTT 子集不被污染；
- 新鲜、降级、过期和查询时间倒退状态；
- 32 位计数器在单次响应和连续样本间跨越 `0xffffffff -> 0`；
- 超半周期歧义、位宽越界、主机时间顺序错误、MCU 处理时间不可能和 RTT 超限；
- 无有效模型时禁止时间换算。
- 未分配节点禁止注册模型，错误启动代次禁止注入样本和查询估计；
- 新启动代次替换旧模型，同代重复注册保持样本；
- 分配撤销和离线会清空模型，恢复后不会沿用旧时钟；
- 模型数量上限、节点 ID 所有权冲突和过去目标时间；
- 安全换算同时覆盖调用方误差门限与目标时刻的未来老化。
- `TimeSync v1` 请求/响应逐字段往返，以及长度、版本、保留位、epoch、频率、位宽、
  tick 范围和半周期边界；
- 确定性 Mock tick、32 位单次响应回绕和默认启动代次变化；
- 分片请求经过 Mock Node、Remote Core、请求匹配后形成四时间戳并进入节点模型；
- 缺失实际发送边界、同代计数器配置变化和 Mock 节点重启换代。
- 周期首次采样、单轮派发上限、同节点不重叠、固定间隔和待处理容量；
- 首发时间只记录一次，重试不覆盖；最终超时清理同步状态；
- 节点离线、撤销分配和恢复在线后的取消及重新采样生命周期。

这些测试只证明算法和边界条件，不代表实体 CAN 适配器、MCU 时间戳位置或晶振稳定
性已经验证。

## 后续接入点

时钟算法、同步协议、Mock BSP、`toolbusd` 周期闭环和节点生命周期已经接入 CMake
测试体系。后续仍需要：

1. 为周期、容量、采样质量和拒绝原因增加正式配置与只读运行时观测；当前使用主机侧
   固定安全默认值，同步结果尚未暴露到 IPC 或监控指标；
2. 实体固件提供稳定自由运行计数器的 BSP 锁存点和可靠 `boot_epoch`，并通过统一硬件
   环境验证 CAN/CAN-FD 排队、不对称延迟、晶振和计数器回绕；
3. 独立运动组协调器已经只接受 `host_to_node_time()` 的成功结果，并冻结所有成员的
   启动代次、模型代次、估计值和换算 tick；当前尚未接入守护进程主循环；
4. COMMIT 使用冻结结果而不重新换算，新样本可以更新活动模型但不能改写该事务；
5. 运行中节点离线、代次变化或误差越界时，由后续运行期运动组策略决定共同边界停机，
   本模块不自行发送停止命令。

后续协议演进仍需定义硬件时间戳质量、模型代数和更细错误码。v1 保留字段必须为零，
未来扩展必须提升载荷版本或显式协商，不能静默复用字段。
