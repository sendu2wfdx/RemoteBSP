# 产品定位与上位机配套架构

## 产品定位

RemoteBSP 是受 Klipper 主机/MCU 分工启发、面向通用机电设备重新设计的分布式
控制平台。Linux 负责运动规划、设备协议和业务逻辑；MCU 负责按时间执行原子硬件
操作、维护有界队列并实施必要的本地安全策略。

RemoteBSP 不是 Klipper 协议兼容实现，也不提供完整的 G-code、打印机业务或通用
CNC 插补器。它复用的是“Linux 规划、MCU 确定性执行”的问题分解，并进一步面向
CAN/CAN-FD 多节点、通用硬件资源、故障隔离、静态固件生成和可观测性扩展。

项目首先服务于使用 Linux 主控开发多节点机电设备的系统工程师。核心价值不是
远程翻转一个 GPIO，而是避免每增加一块工具板就重新实现通信协议、固件资源映射、
升级、运动同步、故障处理和诊断工具。

## 产品组成

产品由三个正式层次组成：

1. RemoteBSP Studio：板卡工程、资源映射、冲突检查、固件生成、构建、烧录和回读；
2. RemoteBSP Runtime：`toolbusd`、`libremotebsp`、节点管理、资源访问、调度、同步、
   遥测和故障隔离；
3. RemoteBSP Node：运行在 MCU 上的通用实时执行固件和板级资源适配器。

Mock、数字孪生、故障注入和记录回放贯穿上述三层，是验证和诊断能力，不作为与
三层并列的第四套产品。

## 上位机配套方向

后续上位机可以采用类似 Moonraker 与 Fluidd 的分层，但不复制其打印机业务：

```text
设备应用 / 自动化流程 / Web 控制台
                 |
        RemoteBSP Runtime API
        REST / WebSocket / 事件订阅
                 |
          libremotebsp
                 |
             toolbusd
                 |
       CAN / CAN-FD / USB Bulk
                 |
        RemoteBSP MCU 节点
```

Runtime API 是面向人机界面和自动化系统的服务层，负责：

- 节点、资源、租约、运动组和故障状态的稳定对象模型；
- 命令请求、异步事件和遥测订阅；
- 用户身份、权限、审计和多客户端协调；
- Studio 工程、构建记录、节点固件和配置哈希之间的关联；
- 对外提供版本化 REST/WebSocket API，但不直接访问 SocketCAN 或 USB。

Web 控制台只调用 Runtime API，负责拓扑、实时控制、运动状态、趋势、告警、日志和
升级工作流。Studio 与运行时控制台可以共享视觉组件，但配置构建面和实时运行面必须
保持清晰边界。

第一阶段不急于实现完整上位机产品。应先稳定 `toolbusd` 本地 IPC、资源合同、事件
语义和错误模型，再提供薄的 Runtime API；否则 Web 层会过早固化尚未稳定的底层接口。

## 通用总线与协议转换

I2C 和 SPI 遵循与 Klipper 相同的基本边界：Linux 理解具体芯片寄存器和业务语义，
MCU 只执行有界的原子总线事务。Studio 静态配置物理总线和逻辑设备端点，运行时命令
只引用逻辑资源 ID，不携带任意引脚复用请求。

板载协议转换器作为资源提供器：

- SPI 转 UART 对外暴露普通 UART；
- SPI 转 GPIO 对外暴露 GPIO 或 GPIO Bank；
- SPI 转 I2C 对外暴露 I2C Bus/Device；
- 内部使用的 SPI 控制器不再同时作为通用 SPI 暴露。

MCU 适配器可以理解转换芯片自身的寄存器，但不能理解连接在转换后端的传感器、
阀门、GPS、Modbus 或其他设备业务协议。

## 高速接口边界

RemoteBSP 不把所有高速接口透明隧道到 CAN。系统采用控制面与数据面分离：

- CAN/CAN-FD：节点发现、心跳、运动、安全、低速控制和故障事件；
- USB Bulk 或后续高速链路：连续采样、大块 UART/SPI 数据、文件和其他高吞吐流；
- 高速数据链路断开时，不得无条件把全部流量降级到 CAN。

高速资源使用统一的有界 Stream 模型，能力合同至少包含持续/峰值吞吐量、块大小、
缓冲容量、时间戳、背压或丢弃策略、最大延迟及允许使用的物理链路。网络接口若作为
节点主链路，应实现为新的 `LinkTransport`；若只是板载 SPI 网络控制器，则只有低速
控制场景适合通过 CAN 暴露 Socket 资源，不能把 100 Mbit/s 以太网数据塞入 1 Mbit/s
CAN 链路。

## 当前开发与硬件验收边界

当前阶段只实现和验证协议、Linux 运行时、Studio、Mock MCU、数字孪生、故障注入、
单元测试和交叉编译，不自动操作实体板卡。所有依赖示波器、逻辑分析仪、真实 CAN
适配器、电机、限位、灯带或外设的项目统一记录到硬件验收清单，由用户准备环境后
集中执行。
