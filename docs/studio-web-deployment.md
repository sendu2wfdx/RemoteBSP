# Studio Web 受控 ST-Link 部署

本地 Studio Web 的部署入口默认关闭。启动服务时必须显式加入
`--enable-stlink-deployment`，并配置固定的 `--toolbusd-socket`、节点 ID、
`remote-cli` 和部署记录目录。浏览器不能提交可执行命令、固件路径、OpenOCD target
配置或 ST-Link 参数；这些边界全部由服务端和已校验构建记录决定。

部署分为两个阶段：

1. “部署前预检”只读取受保护的构建记录和当前运行节点身份，核对板型及用户填写的
   32 位小写 UUID。预检会访问设备，但不烧录，并返回最多 5 分钟有效的一次性令牌、
   四重预期身份和后续步骤。
2. 用户精确填写页面显示的确认短语后，“确认并烧录”消耗令牌。服务端再次解析构建
   产物，调用与 CLI 共用的 `deploy_stlink`，执行 program、verify、reset，等待同一
   UUID 节点重连，再核对板型、工程、配置和固件输入身份。最后通过共用的
   `DeploymentRecord` 后端原子保存部署记录。

执行请求只接受确认令牌、确认短语和三个有界超时字段。未知字段会被拒绝，令牌不可
重复使用；任何错误都不会返回“已核验成功”。由于烧录失败后设备的实际状态可能未知，
页面会要求重新预检，而不会根据 HTTP 失败自行推断板上仍运行旧固件。

部署记录证明写入和运行时身份核验，不证明 GPIO、BUS、PWM、运动或波形通过实体测试。
没有可用调试器时，只能通过 Mock reader 和假烧录执行器验证软件流程，不能把这种测试
记为实烧结果。
