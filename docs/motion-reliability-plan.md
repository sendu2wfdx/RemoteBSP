# 运动可靠性与跨板同步验证计划

## 目的与边界

本文固定 RemoteBSP 第一阶段运动执行器的安全语义、Mock/单元测试基线，以及下一
阶段跨板同步的协议约束和纯软件事务闭环。当前阶段不连接实体板，不对 STEP 抖动、跨板偏差或停止
延迟作实测结论；这些数据统一留到硬件环境搭建完成后验收。

Mock 是功能级、确定性参考模型，用于验证队列、状态、边沿
顺序和故障恢复；它不是 MCU 中断延迟或 CAN 时延的周期精确仿真器。严格的 compare
迟到判定由固件单元测试覆盖。

## 已固定的单节点语义

### 入队与顺序

- 运动段序号从 1 开始严格递增。重复段、旧段和跳号段都拒绝，且不改变已接受段。
- 传输层的重复请求应由请求缓存返回原响应；若重复请求穿透到运动队列，连续序号
  校验仍会拒绝，避免重复运动。
- 显式开始时间必须满足最小提前量；自动开始时间只用于无缝追加或空队列首次排程。
- 队列非空时，新段起点必须等于既有队尾终点，不允许重叠或静默插入空隙。
- 最终段之后不能追加运动段；容量、时序、单轴步频和整板总步频均为硬拒绝条件。
- 每次拒绝均计入 `rejected_segments`，便于区分链路重试、规划错误和容量压力。

### 执行与迟到

- `ARMED` 的段只在绝对开始时间到达后启动；`RUNNING` 使用同一单调时钟调度所有轴。
- 段起点、STEP 上升沿和有后继段的连续边界属于严格事件。超过 compare 迟到预算
  时不补步、不启动下一段，直接锁存 `TIMING` 并进入安全状态。
- STEP 下降沿可以晚于名义时刻，因为延长高电平不会增加步数；但若延后已经侵占
  下一脉冲的最小低电平时间，则锁存 `TIMING`，不能输出零宽或过短低脉冲。
- 最终段结束，以及无后继段、即将进入欠载的纯收尾边界，可以安全延后；此时只
  涉及 STEP 拉低或 EN 关闭，不额外产生 STEP。
- 多轴同一时刻到期时由同一次服务处理；DDA 余数只通过整数加法和比较分配。

### 欠载、限位与恢复

- 非最终段执行完且没有下一段时锁存 `UNDERRUN`，清空队列并关闭 STEP/EN。
- 限位在 `ARMED` 和 `RUNNING` 都有效。已经有效的限位必须阻止待启动段使能电机，
  运行中的限位则立即停止整个本地运动组。
- 主动停止、限位、欠载和定时错误均锁存，不允许链路恢复或新段到达后自动续跑。
- 清故障只允许在队列为空时执行。清除后保留累计位置、计数器和最后接受序号；新段
  必须使用下一个序号，并基于新的当前时间重新建立前瞻。
- 当前实现每个节点只有一个运动组，所以组内任一安全输入会停止该节点全部运动轴。
  后续多组隔离必须先引入明确的组资源和本地安全域，不能仅靠应用约定。

## 自动化测试矩阵

| 类别 | 固件执行器 | Mock 执行器 | 判定要点 |
|---|---|---|---|
| 长时间连续运行 | 512 段、双轴、持续补队列 | 512 段、双轴、持续补队列 | 无欠载、步数和位置完全一致、最终关闭 EN |
| 顺序保护 | 首段跳号、重复、后续跳号 | 同左 | 拒绝不污染队列，正确序号随后仍可接受 |
| 时间边界 | 迟到预算等值与超一单位 | 最小提前量等值与少一纳秒 | 边界包含关系固定，不依赖平台舍入 |
| 连续段边界 | 后继段存在时严格迟到 | 运行中追加保持 `RUNNING` | 不短暂启动已经迟到的下一段 |
| STEP 脉宽 | 晚下降沿、低电平被侵占 | DIR 建立时间大于 STEP 低电平 | 不产生重叠脉冲 |
| 零步轴 | 连续段切换 | 连续段切换 | 前段已使能、后段零步时在边界关闭 EN |
| 限位 | 启动前已有效、运行中触发 | 数字孪生脚本触发 | 无额外 STEP，队列清空，故障锁存 |
| 欠载恢复 | 非最终段耗尽后清故障 | 同左 | 不自动续跑，位置保留，序号继续递增 |
| 时间倒退 | MCU 单调时钟由平台保证 | 显式拒绝 | Mock 场景不得倒放时间 |

测试规模 512 段用于快速回归和环形队列多次回绕，不代表实体稳定性时长。硬件阶段
还必须进行更长持续运行与最坏负载测试。

## 跨板 PREPARE/READY/COMMIT 纯软件基线

当前 v1 线格式和独立协调器已经实现以下闭环：

- `PREPARE`、`READY`、`COMMIT`、提交确认和 `ABORT` 都携带同一事务身份；
- 主机在开始事务时一次性冻结每个节点的 `boot_epoch`、时钟模型代次、模型估计和
  节点开始 tick，后续同步采样不会改写该事务的换算结果；
- 只有全体成员返回完全匹配的 READY，协调器才会一次性生成全体 COMMIT 动作；
- 任一成员拒绝、身份不符、重启、准备/提交超时或用户取消，都会转入有界 ABORT
  收敛，并向所有成员产生停止动作；
- Mock 节点对完全相同的 PREPARE/COMMIT 幂等，对同一身份但不同内容硬拒绝。

当前主机协调器尚未接入 `toolbusd` 事件循环和 RequestManager，实体固件也未实现
这些命令。Mock RemoteCore 已完成可执行闭环：PREPARE 使用执行器副本作无副作用
校验，COMMIT 才入真实队列，ABORT、普通运动停止、会话释放和 STEPGEN 租约失效
都能撤销未开始事务。网络分区发生在部分 COMMIT 已送达之后时，纯软件无法撤回
已经到达的提交，仍必须依赖未来的短期许可租约或硬件安全线覆盖。

### 事务身份与状态机

每个跨板运动事务至少携带：

- `group_id`：运动组和安全域标识；
- `transaction_id`：本次事务唯一标识；
- `plan_generation`：同一运动计划的单调代数；
- `plan_digest`：规范编码后的完整计划摘要；
- `boot_epoch`：节点每次启动变化的会话代数；
- 全局开始时间、段数量、总持续时间和资源租约代数。

建议节点状态机为：

```text
EMPTY -> PREPARED -> READY -> COMMITTED -> RUNNING -> COMPLETE
            |          |          |           |
            +----------+----------+-----------+-> CANCELLED/FAULTED
```

准备区与正在执行的队列必须隔离。新事务不能覆盖已提交计划；节点重启后准备区清空，
旧 `boot_epoch` 的延迟报文全部拒绝。

### PREPARE

主机先向每个成员发送该节点负责的段和共同事务身份。节点在不武装输出的前提下验证：

- 轴和运动组存在，资源租约有效且没有冲突；
- 段序号、时序、速率、队列容量和内容摘要一致；
- 当前时钟模型处于 `SYNCED`，误差上界满足运动组要求；
- 计划有足够的准备、提交确认和 compare 安全提前量；
- 本地没有限位、急停、驱动或已锁存运动故障。

相同事务身份和摘要的重复 PREPARE 返回同一结果；相同身份但摘要不同必须返回冲突，
不能覆盖。准备状态带过期时间，过期后自动释放但不得影响其他组。

### READY

READY 不只返回布尔值，还应回报：

- 事务身份、摘要和节点 `boot_epoch`；
- 已预留段数、队列容量和前瞻时间；
- 时钟模型代数、当前同步状态和误差上界；
- 节点可接受的最早全局开始时间；
- 准备状态过期时间和失败原因。

主机以全部关键成员中最晚的可开始时间，再加提交确认保护窗，选择统一开始时间。

### COMMIT

COMMIT 携带完整事务身份、摘要、时钟模型代数和最终全局开始时间。节点仅在以下条件
全部满足时进入 `COMMITTED`：准备记录完全匹配、模型仍在允许误差内、开始时间仍有
足够提前量、资源与安全输入仍有效。节点将全局段边界一次性换算为本地 tick，并冻结
该事务使用的换算代数；同步模型更新只能影响尚未提交的事务。

重复 COMMIT 必须幂等返回已提交状态。旧代数、摘要不符、未准备、已过期或开始时间
过近均拒绝。节点回报最终本地开始 tick 和误差承诺，主机必须在保护截止时间前收齐
所有关键成员确认。

分布式链路无法在节点任意失电或网络分区时提供无条件原子提交。若部分节点已收到
COMMIT 后失联，软件取消不能保证到达。因此：

- 开始时间前未收齐确认时，主机向所有可达成员发送带事务身份的组停止；
- 安全关键设备应使用硬件急停、共享使能或独立同步/许可线覆盖分区风险；
- 后续可选短期执行许可租约，使节点在开始前未持续收到许可时自行取消；
- 产品文档必须区分“健康链路同步承诺”和“网络分区下的硬件安全等级”。

### 时钟模型

主机使用四时间戳样本建立仿射映射：

```text
local_tick = scale * global_time_ns + offset
```

实现约束：

- MCU 在接收路径尽早锁存本地接收 tick，并在响应发送前锁存发送 tick；
- 主机优先选取低往返时延样本，以滑动窗口稳健拟合偏移和频率，拒绝拥塞离群值；
- 误差上界包含时间戳分辨率、往返不对称、拟合残差和样本老化后的漂移增长；
- 至少区分 `UNSYNCED`、`SYNCED`、`DEGRADED`，并使用最少样本数、最大样本年龄、
  最大残差和最大误差上界作为显式门槛；
- 短位宽硬件计数器先回绕安全地扩展到逻辑 64 位，再参与拟合；
- 运行期间不突跳本地硬件时钟，不重算已经提交的 STEP 边沿。

### 跨板 Mock 验证场景

当前确定性模拟已覆盖协议编解码、全员 READY 门、重复请求、内容冲突、主动取消、
准备/提交超时、提交拒绝、节点重启、活动时钟更新后仍沿用冻结换算，以及 Mock
RemoteCore 中 PREPARE 无副作用、COMMIT 单次入队、开始前 ABORT、普通停止、会话与
租约失效。时钟模型的漂移、离群值、回绕和老化由独立时钟测试覆盖。后续仍需覆盖：

1. 接入守护进程后的 CAN 延迟、抖动、不对称、丢包和乱序；
2. 长时间轨迹中队列低水位、单节点欠载和共同段边界停止；
3. 本地限位与跨板停止分别计时，不混用同一安全精度声明。

## 实体板统一验收清单

测试环境就绪后，每轮必须记录板型、固件哈希、完整 `.config`、供电、温度、CAN
仲裁/数据速率、总线负载、探头和采样率。建议统一验收：

- F072、F103、G431 分别验证 STEP 高/低宽度、DIR 建立时间、EN 极性和共享 EN；
- 单轴与满轴数在低、中、最高批准步频下持续运行，核对命令步数、逻辑分析边沿数和
  固件位置计数，至少包含多次方向切换与队列环形回绕；
- 逐级增加 CAN/CAN-FD 负载，测 compare 最大迟到、ISR 最坏耗时和队列最低前瞻；
- 在 STEP 高电平、低电平、段边界和方向切换附近触发限位，测最后 STEP 到 EN 关闭
  的最坏延迟，并确认无额外上升沿；
- 制造队列欠载、主动停止、链路中断、节点复位和驱动故障，确认安全输出、锁存原因、
  显式恢复以及位置不可自动信任的提示；
- 两块同型板及 F103/G431 混合组合验证同步启动、长时间漂移和共同边界停止；
- 跨板限位单独测量输入消抖、CAN 仲裁、远端处理和电机停止总延迟，不引用本地限位
  的结果；
- 保存原始 VCD/CSV、固件状态快照和测试脚本，失败用例必须可重复回放。

只有完成以上实体测试后，文档才能把“已编译/已通过 Mock”升级为“已在硬件验证”。
