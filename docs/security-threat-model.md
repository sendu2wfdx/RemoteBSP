# RemoteBSP 安全威胁模型

本文描述当前仓库的软件信任边界、已实现控制和仍需关闭的风险。它不是安全认证，
也不能替代目标设备、Linux 主机、网络和生产流程的部署审计。

## 保护目标

- 运动、GPIO、PWM、总线事务和升级命令只能由获准主体发出；
- 跨板运动的计划身份、资源租约、时钟代次和提交状态不能被静默替换；
- Studio 工程、固件、配置哈希、生产记录和实体测量证据可追溯且不可混淆；
- 单个恶意、故障或离线节点不能阻塞其他节点，也不能绕过本地安全停机；
- API 密钥、设备身份、制造信息和审计数据不得意外泄露；
- 畸形输入、请求洪泛和超大对象只能消耗预先限定的资源。

## 信任边界

```text
浏览器 / 自动化客户端
        │ HTTP（只读接口 + 认证回环 GPIO 最小控制面）
        ▼
Runtime API
        │ remote-cli / libremotebsp
        ▼
toolbusd Unix Domain Socket
        │ Remote Packet + Fragmentation
        ▼
CAN / CAN-FD / USB
        │
        ▼
MCU Remote Core → BSP → 物理输出

Studio 工程 → Kconfig → 构建归档 → 烧录/回读（后两步待实现）
```

Runtime、`toolbusd`、总线节点和 Studio 构建面属于不同信任域。HTTP 认证不能替代
Unix 套接字权限；Unix 套接字权限不能证明远端 MCU 固件可信；生产记录的 SHA-256
只能发现内容变化，不能证明记录由可信签名者生成。

## 攻击者与假设

- 未获授权的网络客户端可连接到被错误暴露的 Runtime 端口；
- 同机低权限进程可能尝试连接 `toolbusd`、读取构建产物或抢占资源；
- 总线上可能出现损坏、重放、伪造或洪泛帧；当前协议 CRC 只检测传输损坏，不提供
  消息认证或机密性；
- 某个 MCU 可能故障、重启、卡死或运行不匹配固件；
- Studio 可导入不可信工程、批次和历史记录；文件名、Markdown 和压缩包内容均按
  不可信输入处理；
- 能直接探测、替换或刷写实体板的攻击者不在当前纯软件防护能力内，必须由机箱、
  调试口策略、安全启动或生产管控补充。

## 当前控制与剩余风险

| 风险 | 当前控制 | 仍需关闭 |
|---|---|---|
| 未认证 HTTP 访问 | 无认证模式只允许数字回环地址；非回环强制 API key 身份和 `runtime.read` 权限，使用固定长度摘要比较、最小公开存活探针并拒绝 URL 密钥 | 细粒度角色、TLS/反向代理、限速、密钥热撤销与密钥文件属性强制校验 |
| 本地命令越权 | `toolbusd` 独占总线；Unix 套接字固定为 `0660`，由所有者/组控制 | 校验对端凭据、专用服务用户、组成员审计和 systemd 加固 |
| 重放与副作用重复 | 会话 ID、请求 ID、严格响应匹配、MCU 有界去重缓存 | 总线消息认证、密钥轮换和跨重启防重放策略 |
| 跨板部分提交 | PREPARE/READY/COMMIT/ABORT、身份/启动代次冻结、STM32 参与者和全组取消 | 可靠实体启动代次、部分 COMMIT 网络分区恢复；COMMIT 后只能尽力停止 |
| 资源争用 | 静态资源表、主机会话级租约、固件 STEPGEN 独占租约、运行期禁止改线；HTTP GPIO 控制把服务端权限、稳定 UUID、节点代次、剩余 TTL 与幂等键贯穿到 `toolbusd` 最终准入；GPIO 首次创建保持低电平，释放/过期/关停会安全写低并执行 `GPIO_CLOSE`，不确定 Close 冻结单资源并幂等重试，固件对象绑定创建会话；结构化错误和单一绝对期限强制“可能已提交即不可直接重试” | 跨进程可查询操作账本、跨租约过期的 exactly-once 查询、租约操作者持久审计、实体最坏停机延迟和管理面撤销策略 |
| 畸形或超大输入 | 协议长度/枚举/CRC、IPC 固定上限、HTTP 工作线程上限、Studio 导入上限 | 模糊测试覆盖报告、长期洪泛与内存压力基线 |
| 节点故障扩散 | 节点/资源级超时和健康状态、有界队列、离线隔离、本地安全停机 | 实体总线饱和、卡死外设与网络分区故障矩阵 |
| 构建/记录篡改 | 规范配置哈希、产物 SHA-256、确定性资料包和显式证据层级 | 签名、可信时间、密钥保管、构建来源证明和回读闭环 |
| 固件降级或参数破坏 | Katapult APP 上界保护、参数双页提交和 CRC | 签名固件、反回滚策略及三类板卡掉电恢复验收 |
| 敏感信息泄露 | Runtime 错误结构不回显内部快照，HTTP 响应禁止缓存；审计不保存密钥、原始路径或请求体，并使用有界非阻塞输出 | 持久审计的轮换、访问控制、完整性保护和备份策略 |

## 安全不变量

后续实现必须保持以下条件：

1. 应用和网页不能绕过 `libremotebsp`/`toolbusd` 直接访问 SocketCAN 或 USB；
2. 认证成功不自动授予写权限，写控制面必须再检查角色、资源租约和幂等身份；
3. 紧急停止不能被普通请求队列阻塞，但也不能被普通 API 冒充；
4. 节点重启、时钟代次变化或计划身份不一致必须使跨板事务失败关闭；
5. 未验证、损坏或来源不明的 Studio 历史记录不能进入“已烧录”或“硬件已验证”状态；
6. 所有队列、线程、载荷、导入文件、记录数量和等待时间必须有固定上限；
7. 任一错误若标记 `possibly_committed=true`，就不得同时标记为可直接重试；调用方必须查询原操作或进入显式恢复流程。
7. Mock、交叉编译和软件模型估计不能标记为实体安全或硬件精度证据。

## 部署基线

- 以专用非 root 用户运行 `toolbusd` 和 Runtime，把获准客户端加入最小权限组；
- 将 Unix 套接字放入该服务用户拥有、不可被普通用户替换的运行目录；
- 非回环 HTTP 必须启用认证，并由受控反向代理提供 TLS、请求大小限制和连接限速；
- API 密钥通过权限受限的密钥文件或服务凭据注入，不写入 URL、项目工程、日志或
  Git 仓库；
- Studio 构建、烧录和生产历史使用独立目录与权限，导入包始终重新校验；
- 保留版本、配置哈希、固件哈希、操作者、目标节点、请求 ID、结果和时间来源，
  但日志不得保存明文密钥或不必要的设备隐私信息；
- 在实体部署前完成总线洪泛、节点伪造、部分提交、服务重启、磁盘损坏和升级中断演练。

## 验收口径

安全边界达到 `verified` 至少需要：认证和权限矩阵自动测试、Unix 套接字与服务用户
部署测试、固定攻击输入集、资源耗尽上限测试、结构化审计记录，以及实体总线和升级
恢复演练。本文中的设计或单元测试只能证明对应软件范围，不能单独关闭实体风险。
